The operator says what they want changed; you find the knob, change it where it is declared, and prove it took. The configuration is split by owner.

**Deployment knobs** live in the store and the recorder, describing infrastructure that is out there running: change the declaration → `bun run deploy` (or `bun run provision` for an infra-only change) → `locus doctor` confirms. **Analysis knobs** are declarations in `config/` at the deployment root and in the analysis package: nothing is deployed and there is nothing to reconcile — the next `locus analyze` reads the file.

## Where each knob is declared

- **`store/deploy.config.toml`** — the retention horizon, which governs every copy of a recording. Then `bun run provision` (reconciles the bucket, no worker rebuild) or `bun run deploy` (provision + ship); the local db comes to the new horizon on the next `locus load` or `locus doctor`.
- **`store/wrangler.toml`** — the worker and its resource bindings. The presence of the `CAPTURE` (Analytics Engine) binding is the single signal for whether AE is part of this deployment; the worker, `doctor`, and you all read it from here.
- **`store/.env`** — credentials: the Cloudflare token and account id, plus the `GOOGLE_API_KEY` when analysis runs on Gemini; gitignored, never committed, the one home every `locus` read and every model call self-serves from.
- **`data/context/<snippet>.md`** under the deployment root — the operator's business frame (what the site is for, what a good and a bad visit mean). Every analysis reads it by the slice set's snippet, so an edit takes effect on the next one. It comes from the operator's mouth, never inferred.
- **`recorder/src/global.js`** — the facade the store builds and vends: capture-time config (masking, drain cadence, a rollout gate), written inline and shipped by `bun run deploy`. The tag on the site carries only the snippet id and never changes. Read the facade's docstring before changing it — it carries the how.
- **`config/cards/`** — the models this deployment can analyze with, one file per card, the file's name the card's name, each with its declared facts: the model's context, the share of it one call may claim, and (locally) its full generation config and the per-image token ceiling screenshots are sent under. A model needs a card here before `locus analyze` can run on it; every card names the client that speaks to it (`conversation = "gemini"`, or `"openai-compatible"` at the card's `base_url`). A Gemini card also declares its per-token prices — the numbers every billed call's dollars are computed from. The card marked `default = true` is what an invocation runs on when it names no `--model`; changing what the deployment analyzes with is moving that mark — nothing to deploy, the next analysis reads it.
- **`config/spend.toml`** — the operator's spend walls over paid analysis: dollar caps per UTC calendar period, shipped with a default cap so a deployment is walled before anyone edits anything; the file's own comment names the keys and how each reads. Read fresh at every paid call, so an edit takes effect immediately — nothing to deploy. Enforced against the ledger beside the db (`spend.jsonl`, one line per billed call); the spend block of `locus status` reports each period's spend against its cap.
- **`config/definitions.toml`** — the operator's definition of a session and of engaged, the numbers the db's `sessions` table is derived by; the file's own comment states the definition and names the keys. An operator adjusting a meaning ("call it a session after an hour, not thirty minutes") is an edit here, then `locus doctor`: the numbers are part of the derivation vintage, so doctor sees the drift and re-derives every session under them — nothing to deploy. A conversion is not a definition and has no key here; what converting means is the business frame in `data/context/<snippet>.md`.
- **`analysis/src/locus/analysis/prompts.py`** — everything the model is told: the grounded-reader contract every analysis is held to (how the evidence reads, that every factual claim cites its moment), the answer-turn closings — what the model is told when it can pull screenshots — and the repair task an answer with invalid citations gets back. The question itself is never here — it is the agent's, composed per invocation. Takes effect on the next analysis, no deploy; changing this file changes how every answer reads the evidence.
- **`analysis/src/locus/analysis/select_screenshots.py`** — the activity-screenshot interval default: how densely screenshots sample the window's active spans, overridable per analysis with `--screenshot-interval`. Takes effect on the next analysis, no deploy.

Read `store/README.md` in full before touching any deployment knob; it carries the exact commands — run them, don't restate them.

The list above is routing, not a boundary: it is where the declared configuration lives, and the deployment is the operator's own code, so a want with no declared knob is a code change made where the behavior lives. Reading the code first is a precondition — the modules are small, and a small constant can decide what exists downstream: a fold window in the event-stream composer decides which behavior classes ever reach a model. Find it, read it, change it, and prove it took the same way as any knob: doctor for deployed surfaces, a run for analysis ones.

## The cases, by request

**Retention.** `retention_days` in `deploy.config.toml` is both the storage-cost bound and how long visitor recordings are kept at all — ask which constraint the operator actually means. Lowering it expires older chunks on R2's next lifecycle pass and drops the local db's copy of them on the next `locus load` or `locus doctor`, both irreversibly; raising it keeps more for longer, but recovers nothing already expired. Say what a lowering will take before running it — `locus status` counts what is loaded — because analyses whose citations point into those recordings survive as findings that can no longer be replayed.

**Public access.** There is no knob: the bucket holds visitor recordings, so provision and doctor assert it is private outright rather than reading a field that could say otherwise. An operator who wants session recordings publicly readable is taking on a real liability — surface that plainly.

**Analytics Engine, on or off.** AE is optional and decoupled from capture: the worker writes telemetry when the `CAPTURE` binding is present and no-ops when it is not.
- *Off:* comment out the `[[analytics_engine_datasets]]` binding in `wrangler.toml` and redeploy. Capture keeps working, the observability *rates* plane goes dark, old AE data ages out on its own, and doctor stops expecting the binding.
- *On, when they never had it:* Analytics Engine must be enabled on the Cloudflare account first — until the entitlement is live, the deploy fails on the binding. Then ensure the binding is present and redeploy.
- With AE off, observability falls back to R2's exact plane — arrivals, storage, operation counts — with no rates at all. Tell the operator which plane their answer came from.

**Masking.** Capture-time redaction, in the facade (`recorder/src/global.js`), changed and shipped like any capture config above. Because masking is record-time and irreversible, a change only ever affects future recordings — so timing matters: once a site's tag is live, every recording accumulates under whatever masking is in force, unrecoverably, and a site with sensitive input or content beyond the credential fields the recorder always masks (recorder/README.md) wants its rules set as early as possible. A deploy reaches new page loads only: pages already open keep recording under the old bundle — old masking included — until their tabs die, which for parked tabs is weeks, so a masking fix is not fully in force the day it ships. Something sensitive already recorded is remediable by deletion: remove that span's chunks from the bucket and the derived rows, screenshots, and analyses beside the db — the cost is that interval's coverage.

**Another site.** Adding a site is the setup skill's.

**Which backend analysis runs on, and its key.** The switch is the `default = true` mark in `config/cards/`: move it to a local card or a Gemini card — nothing to deploy, the next analysis reads it. A Gemini card also needs `GOOGLE_API_KEY` in `store/.env`, written there by the operator themselves; without it a Gemini analysis fails loud naming the key, and the key by itself changes nothing. How to weigh the backends, and the machine check before going local, are the setup skill's backend step; past setup cost, what justifies local is per-call cost or keeping data off a third party.

**What the analysis costs, and how it reads.** Two different requests arrive in the same words ("the analysis is too expensive", "it's missing things"). Screenshots dominate a call, so the cost levers are how many ride the model-payload (the interval knob) and what each costs on the wire, which is the model card's declaration in `config/cards/` — a local card's per-image token ceiling, a Gemini card's flat-priced resolution tier per screenshot kind; an analysis is priced against the model-payload it actually sends up front, under the share of the model's context its card lets one call claim, and the rest of the context is what the conversation grows into. Measure before and after rather than reasoning about it. If the request is really about *quality* — what an answer notices, how it judges a visit — that is the question the agent composes, the grounded-reader contract in `prompts.py`, and the business frame in `data/context/<snippet>.md`, not a cost knob.

**Account or credentials.** The account id and token live in `store/.env`, the one home `locus` reads and AE queries self-serve from. Moving accounts is a new `store/.env`; the bucket is named in `store/wrangler.toml` and read from there, so nothing else changes. The new account needs R2 — and Analytics Engine, if used — enabled before anything will deploy.

## Not done until it's confirmed

For a deployment knob: `locus doctor` asserts the live deployment against the declaration and names anything that did not land. A change you cannot confirm with doctor is not done.

For an analysis knob: run it. A `locus analyze` invocation shows what the change did to the token economics for free; sending the analysis shows what it did to the answer.
